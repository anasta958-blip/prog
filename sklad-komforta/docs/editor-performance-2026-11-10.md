# Замеры редакторов КП, ПКП и комплектации — 10.11.2026

Замеры ниже выполнены на Windows командой
`flutter test --no-pub --reporter expanded test/quote_calculation_benchmark_test.dart`.
Это медиана 10 прогретых вызовов расчётного движка в отладочном Dart VM,
в микросекундах. «Частичный» обрабатывает изменение количества одной строки;
«полный» проходит всё предложение. В сложном сценарии добавлены денежный
конвейер и правило `variant_calculation`, которое срабатывает при изменении
итога варианта. Оба сценария изменяют одну и ту же позицию в отдельных
копиях документа.

| --- | --- | ---: | ---: | ---: |
| КП | простые | 100 | 81 | 1671 |
| КП | простые | 500 | 206 | 3329 |
| КП | простые | 1000 | 112 | 4586 |
| КП | сложные | 100 | 2607 | 3615 |
| КП | сложные | 500 | 10780 | 14484 |
| КП | сложные | 1000 | 23466 | 30830 |
| ПКП | простые | 100 | 15 | 382 |

| ПКП | простые | 1000 | 122 | 4582 |
| ПКП | сложные | 100 | 1956 | 2558 |

| ПКП | сложные | 1000 | 21435 | 28632 |

Эти числа не включают построение виджетов, запись черновика и серверное
сохранение. Поэтому по ним нельзя подтвердить цель в пять раз для полного
ввода и задержку до кадра менее 50 мс. Вариантное правило закономерно
требует обработки всех строк варианта.

Flutter Web test runner завис на этапе загрузки как в Chrome, так и в Edge.

Для варианта с 50 и более позициями редакторы КП, ПКП и комплектации теперь
используют `CustomScrollView` и отдельный `SliverReorderableList` для каждого
раздела. Порог учитывает все разделы и категории варианта. Проверки Flutter
прокручивают длинный раздел: дальняя строка сначала отсутствует в дереве
виджетов, затем появляется при прокрутке; ввод, фокус и перетаскивание
сохраняют значения. Проверены перенос категорий и разделов в большом варианте,
добавление строки в раздел перед другим длинным разделом и ввод в комплектации
с несколькими разделами. В документе с 1000 позициями в 10 разделах при
первом кадре смонтировано менее 60 строк. Для небольших вариантов остаётся
прежняя структура экрана.

После передачи категории изменённой строки в частичный расчёт и исключения
повторного прохода по строкам, чьи формулы не зависят от результатов правила
варианта, повторён тот же расчётный benchmark. Медианы сложного сценария на
1000 строк (мкс):

## Профильная Web-сборка редактора

Отдельный стенд открывает настоящий редактор КП в Edge и прокручивает первую
строку в видимую область. Затем 65 раз вызывает обработчик её штатной кнопки
увеличения количества. Первые 5 вызовов прогревают движок; для оставшихся 60
измеряется интервал от вызова обработчика до `postFrameCallback`. Браузер
работает с обычными часами, без `--virtual-time-budget`.

```powershell
flutter build web --profile --no-pub --no-wasm-dry-run -t benchmark/quote_editor_frame_web.dart
python benchmark/edge_editor_frame.py
```

Стенд использует `websocket-client` для протокола отладки Edge. Скрипт
самостоятельно меняет относительный `base href` в сгенерированном файле
`build/web/index.html`, открывает шесть вариантов документа и завершает Edge.

| Строк | Правила | Медиана, мс | 95-й процентиль, мс |
| ---: | --- | ---: | ---: |
| 100 | простые | 20,7 | 30,1 |
| 100 | сложные | 20,9 | 35,1 |
| 500 | простые | 22,2 | 33,9 |
| 500 | сложные | 19,9 | 29,1 |
| 1000 | простые | 20,7 | 31,6 |
| 1000 | сложные | 22,5 | 34,3 |

На этом стенде все шесть 95-х процентилей ниже 50 мс. Это время до завершения
кадра Flutter в профильной Web-сборке; оно не включает доставку аппаратного
события браузером, вывод кадра на монитор и запись локального черновика.
Повторный полный прогон дал 34,6 мс для 95-го процентиля сложного документа
на 1000 строк.
Исторического замера полного редактора до оптимизации нет, поэтому цель по
пятикратному ускорению полного ввода пока не подтверждена.

Серверное сохранение пока не измерено: локальные PostgreSQL и Redis
недоступны. Для VM добавлен интеграционный бенчмарк сохранения КП и
комплектации на 100, 500 и 1000 строк с простыми и сложными правилами.
Он создаёт отдельную тестовую БД, выполняет один прогревочный и пять
измеряемых HTTP PUT для каждого размера. При прогреве ручные строки
регистрируются в каталоге; следующие запросы используют выданные ID.
Тест печатает медиану, минимум и максимум,
а после каждого размера проверяет UUID и полный порядок строк повторным GET.
Время включает HTTP, расчёт и запись БД; оно измеряется отдельно от ввода.

```powershell
$env:SKLAD_BENCH_DOCUMENT_SAVE = '1'
$env:SKLAD_TEST_POSTGRES = 'Host=localhost;Database=postgres;Username=...;Password=...'
$env:SKLAD_TEST_REDIS = 'localhost:6379'
dotnet test tests/api-integration/SkladKomforta.Api.IntegrationTests/SkladKomforta.Api.IntegrationTests.csproj --filter FullyQualifiedName~BenchmarkQuoteAndOrderSaveAgainstRealDatabase --logger 'console;verbosity=detailed'
```

Учётной записи PostgreSQL нужно право создавать тестовую БД; Redis нужен
интеграционному стенду. Пока переменные не заданы, тест пропускается.
Исторического замера серверного сохранения до пакетной записи нет.
Отдельно нужно повторить профильный замер на Windows.
Попытка `flutter build windows --profile --no-pub` на этом стенде завершилась
до компиляции: для плагинов требуется поддержка символических ссылок Windows,
а режим разработчика системы выключен.
