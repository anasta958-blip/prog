## Профильная Web-сборка редактора

Отдельный стенд открывает настоящий редактор КП в Edge и прокручивает первую
строку в видимую область. Затем 65 раз вызывает обработчик её штатной кнопки
увеличения количества. Первые 5 вызовов прогревают движок; для оставшихся 60
измеряется интервал от вызова обработчика до `postFrameCallback`. Браузер
работает с обычными часами, без `--virtual-time-budget`.

```powershell
flutter build web --profile --no-pub --no-wasm-dry-run -t benchmark/quote_editor_frame_web.dart
python benchmark/edge_editor_frame.py
```

Стенд использует `websocket-client` для протокола отладки Edge. Скрипт
самостоятельно меняет относительный `base href` в сгенерированном файле
`build/web/index.html`, открывает шесть вариантов документа и завершает Edge.

| 500 | простые | 22,2 | 33,9 |
| 500 | сложные | 19,9 | 29,1 |
| 1000 | простые | 20,7 | 31,6 |

На этом стенде все шесть 95-х процентилей ниже 50 мс. Это время до завершения
кадра Flutter в профильной Web-сборке; оно не включает доставку аппаратного

Повторный полный прогон дал 34,6 мс для 95-го процентиля сложного документа

Исторического замера полного редактора до оптимизации нет, поэтому цель по
пятикратному ускорению полного ввода пока не подтверждена.

Для VM добавлен интеграционный бенчмарк сохранения КП и комплектации на 100,
500 и 1000 строк с простыми и сложными правилами.
Он создаёт отдельную тестовую БД, выполняет один прогревочный и пять
измеряемых HTTP PUT для каждого размера. При прогреве ручные строки
регистрируются в каталоге; следующие запросы используют выданные ID.
Тест печатает медиану, минимум и максимум,
а после каждого размера проверяет UUID и полный порядок строк повторным GET.
Время включает HTTP, расчёт и запись БД; оно измеряется отдельно от ввода.

```powershell
$env:SKLAD_BENCH_DOCUMENT_SAVE = '1'
$env:SKLAD_TEST_POSTGRES = 'Host=localhost;Database=postgres;Username=...;Password=...'
$env:SKLAD_TEST_REDIS = 'localhost:6379'
dotnet test tests/api-integration/SkladKomforta.Api.IntegrationTests/SkladKomforta.Api.IntegrationTests.csproj --filter FullyQualifiedName~BenchmarkQuoteAndOrderSaveAgainstRealDatabase --logger 'console;verbosity=detailed'
```

Учётной записи PostgreSQL нужно право создавать тестовую БД; Redis нужен
интеграционному стенду. Пока переменные не заданы, тест пропускается.
Исторического замера серверного сохранения до пакетной записи нет.
Отдельно нужно повторить профильный замер на Windows.
Попытка `flutter build windows --profile --no-pub` на этом стенде завершилась
до компиляции: для плагинов требуется поддержка символических ссылок Windows,
а режим разработчика системы выключен.

### Локальное исправление сводки после замера рабочего сайта

Профиль браузера показал длинные кадры при наборе в рабочем КП: 20 кадров
дольше 50 мс, 95-й процентиль среди них 55,7 мс. Самые длительные скрипты
выполнялись в callback кадра `main.dart.js` около 45–47 мс. Это указывает на
работу Flutter в кадре, но не на конкретный виджет. В локальном коде сводка
варианта и типа несколько раз за одно перестроение проходила все позиции;
теперь каждая сводка вычисляется один раз. Заголовок категории также теперь
строит денежные подписи при уведомлении об изменении итога: раньше после
первого изменения он мог показывать старое значение до полного перестроения.
Добавлен тест двух последовательных изменений в длинном разделе.

После этих изменений повторены все 24 сценария для каждого платформенного
стенда. В таблице 95-й процентиль от изменения числового поля до кадра,
