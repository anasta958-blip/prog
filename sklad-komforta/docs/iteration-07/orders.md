# Итерация 07. Комплектация

Комплектация — документ карточки канбана со специализацией «Комплектация»:
что закупается и ставится на объект. Создаётся переносом из КП/ПКП или
кнопкой «Создать комплектацию». Цен нет.

## Данные (`migrations/tenant/0037_orders.sql`)

- `orders` — шапка: название (= адрес объекта = название карточки), тип
  объекта, заказчик, исполнитель, менеджер, РОП, ссылка на исходное КП
  (`source_quote_id`). Одна комплектация на карточку.
- `order_categories` → `order_sections` → `order_positions` — дерево, как в
  КП, без типов и вариантов. В категории несколько разных разделов можно,
  дубликат раздела каталога — нет (уникальный индекс и проверка запроса).
- Позиция: системные колонки (наименование, маркировка, единица, количество) и
  `values` — значения полей, назначенных канбану комплектации («Поля в
  канбанах»), по коду поля. Служебные колонки сервера:
  - `is_reorder` — дозаказ;
  - `source_key` — отпечаток строки, перенесённой из КП (по нему работает
    повторный перенос; у строк, добавленных вручную, `NULL`);
  - `source_quantity` — количество в КП при последнем переносе.
- `order_invoices` — PDF-счета (до 20 МБ) в MinIO; ссылки на скачивание и
  загрузку живут 5 минут.

## Настройки канбанов

Хранятся в черновике конфигурации (`WorkflowDraft`/`WorkflowColumnDraft`) и
материализуются `WorkflowOrderConfiguration` при активации и сохранении
настроек:

- `WorkflowColumnDraft.TransferTo` (`workflowCode`, `columnClientId`) —
  столбец-триггер. Из КП/ПКП — только в канбан комплектации, из комплектации —
  только в канбан КП → `workflow_column_transfers`.
- `WorkflowColumnDraft.ReorderFrom` — у канбана комплектации не более одного
  столбца: позиции, добавленные в нём и правее, — дозаказ →
  `workflow_columns.reorder_from`.
- `WorkflowDraft.OrderSettings` (`objectTypes`, `shipmentStatuses`) —
  справочники канбана комплектации → `workflow_order_options`.
- Поле «Статус отгрузки» (`shipment_status`, тип «Справочник») доступно в
  «Поля в канбанах» канбана комплектации без поля в каталоге; его значения —
  справочник канбана (`workflow_order_options`), а не справочник каталога.
- Тип поля «Выбор значения» (`enum`) и незадействованные системные поля
  «Тип цены» (`price_type`) и «Проверка счёта» (`invoice_check`) удалены из
  реестров полей (сервер и клиент): их функцию выполняет «Справочник».
  Значение `enum` в ограничении таблицы (миграция 0019) остаётся, так как
  применённые миграции не меняются; новых полей с ним создать нельзя.

Клиент перед сохранением удаляет недействительные ссылки переноса (удалённый
канбан или столбец, сменившийся тип канбана). В интерфейсе: у столбцов КП и
комплектации — «Попав в этот столбец, перенести…», у комплектации — флажок
«Дозаказ с этого столбца» и списки «Типы объекта», «Статусы отгрузки».

## Перенос КП ↔ комплектация

`OrderTransferHandler` (`IKanbanColumnEntryHandler`) вызывается
`PostgresKanbanService.MoveCardAsync` при смене столбца, в той же транзакции:
если перенос невозможен, отменяется и перемещение.

- **КП → комплектация.** Берутся позиции выбранных вариантов (режим
  «вариант») или всех вариантов выбранного типа (режим «тип») одним списком,
  только категорий канбана комплектации и только назначенных ему полей.
  Строки, совпадающие по всем переносимым полям, кроме количества, суммируются.
  - Первый перенос создаёт карточку комплектации с тем же `work_item_id` в
    указанном столбце: название — из КП; заказчик, исполнитель, менеджер, РОП —
    из КП.
  - Повторный перенос: новые строки добавляются (в столбце дозаказа и правее —
    дозаказом), количество обновляется, только если изменилось в самом КП,
    строки, исчезнувшие из КП, удаляются; заполненные в комплектации поля и
    строки, добавленные вручную, не трогаются. Карточка комплектации
    перемещается в указанный столбец.
  - Без выбранного варианта/типа — 409 `order_transfer_selection_missing`; нет
    подходящих позиций — 409 `order_transfer_empty`.
- **Комплектация → КП** только перемещает карточку КП того же рабочего объекта
  в указанный столбец; данные КП не меняются.
- Перемещённая связанная карточка не запускает перенос повторно.
- Карточка, стоящая в столбце-триггере, получает `linkedCards` — пометку
  «В комплектации №…» / «В КП №…».

## Менеджер и РОП (КП, ПКП, комплектация)

- При создании менеджер — создатель карточки, РОП — его руководитель по
  структуре «Сотрудники и структура» (`member_reporting`); без руководителя
  поле пустое. Комплектация из КП берёт обоих из КП.
- При сохранении менеджер и РОП меняются только с правом
  `quotes.manager.change` / `orders.manager.change`; без него сервер оставляет
  прежние значения. Флаг `canChangeManager` в документе делает поля
  редактируемыми в интерфейсе.
- Уже созданные КП не пересчитываются.

## API

| Метод | Путь | Право |
|---|---|---|
| POST | `/api/v1/kanbans/{boardId}/orders` (`{columnId, order}`) | `orders.manage` |
| GET | `/api/v1/kanbans/{boardId}/cards/{cardId}/order` | `orders.view` |
| PUT | `/api/v1/kanbans/{boardId}/cards/{cardId}/order` | `orders.manage` |
| GET | `…/order/pdf` | `orders.view` |
| GET | `…/order/invoices` | `orders.view` |
| POST | `…/order/invoices/uploads` (`{fileName, contentType, byteSize}`) | `orders.invoices.manage` |
| POST | `…/order/invoices/{invoiceId}/confirm` | `orders.invoices.manage` |
| DELETE | `…/order/invoices/{invoiceId}` | `orders.invoices.manage` |

`OrderDetails` содержит `canChangeManager` и `canManageInvoices`. Позиции:
`isReorder`, `fromQuote`. Признаки дозаказа и переноса назначает сервер;
новые позиции, сохранённые, пока карточка в столбце дозаказа или правее,
становятся дозаказом. Значения полей, не назначенных канбану, отбрасываются.

Канбан: `KanbanColumnSummary.transferTo`/`reorderFrom`,
`KanbanBoard.objectTypes`, `KanbanCardSummary.order` (стороны, менеджер, тип
объекта, позиции, дозаказ, счета, номер исходного КП) и `linkedCards`.
Перемещение рассылает сигнал реального времени всем канбанам (`boardId =
null`), так как может затронуть связанную карточку.

## Flutter

- `lib/features/orders/` — `order_models.dart` (`OrderDocument` хранит дерево в
  моделях КП), `order_api.dart`, `order_local_draft.dart`,
  `order_preview_page.dart`.
- `OrderController` (часть библиотеки `quote_controller.dart`) наследует
  `QuoteController`: документ показан как один тип с одним вариантом, поэтому
  таблица позиций, строка ввода с автопоиском, Enter-навигация и ширины колонок
  общие с КП. Точки расширения базового контроллера: `attachesCatalogRelations`
  (связанные позиции не добавляются), `showsMoney` (без сумм),
  `isPositionVisible`/`positionFiltersActive` (фильтры; при фильтрации
  перетаскивание строк отключено), `isPositionHighlighted` (дозаказ: оранжевая
  полоса и заливка).
- `OrderEditorPage` (часть `quote_editor_page.dart`): шапка, фильтры
  «Поставщик» и «Статус отгрузки» — выпадашки с несколькими галочками и
  счётчиком на кнопке («или» внутри фильтра, «и» между фильтрами), счета
  (загрузка PDF, просмотр, скачивание, удаление по праву), локальный черновик и
  выбор при уходе с несохранёнными правками, предпросмотр и печать PDF.
  Шапка редактора высотой `workspaceHeaderHeight` (как блок названия программы
  в боковой панели), кнопки действий прижаты вправо.
- Счета открываются в плавающем немодальном окне без сохранения на диск
  (`lib/features/orders/pdf_viewer_window.dart`, пакет `pdfrx` — PDFium, на Web
  через WASM): нажатием на строку или кнопкой «Открыть»; отмеченные флажками —
  «Открыть выбранные (N)», без отметок — «Открыть все». Окно перемещается за
  заголовок, меняет размер за края и углы, разворачивается кнопкой и
  закрывается только крестиком; программой под ним можно пользоваться.
  Несколько счетов — вкладки (у каждой свой крестик); повторное открытие
  выбирает уже открытую вкладку, новые счета добавляются в то же окно. Окно
  живёт в `PdfViewerHost` рабочей области: остаётся при переходах между
  разделами и закрывается при выходе. Байты берутся по pre-signed URL
  (`OrderGateway.fetchInvoice`); если ссылка истекла,
  `OrderController.invoiceBytes` перечитывает список счетов и повторяет
  загрузку.
- Значение поля-справочника, которого больше нет в справочнике (удалено или
  переименовано), показывается в ячейке оранжевым с подсказкой и первым
  пунктом меню «… (нет в справочнике)», пока не выбрано другое (КП и
  комплектация).
- Окно просмотра PDF показывает полосы прокрутки: вертикальную — когда
  документ не помещается по высоте, горизонтальную — когда страница шире окна.
- Канбан: «Создать комплектацию» и открытие карточки ведут в редактор
  комплектации; карточка показывает сводку и пометку связанной карточки.
- В КП поля «Менеджер» и «РОП» без права только для чтения.

## Печать

`OrderPdfService`/`OrderPdfDocumentRenderer`: шрифты и палитра печати КП;
колонки — №, наименование, маркировка, количество, единица и поля канбана
комплектации; дозаказ подсвечен и подписан. При более чем двух доп. полях
страница альбомная. Предпросмотр (`OrderPreviewPage`) повторяет макет.

## Не входит

Перенос комплектаций из PHP-базы, позиции без связи с каталогом, отправка PDF
по email и в Telegram.
