# Бизнес-правила для переноса

Этот документ является основой acceptance-тестов. Если реализация старого кода противоречит правилам ниже, новая система должна следовать правилам, а конфликт должен быть зафиксирован.

## Организации и доступ

- Каждая организация полностью настраивает себя сама.
- Директор при первом входе создаёт организацию и проходит одноразовый onboarding.
- Директор создаёт роли организации и назначает им права.
- `system_admin` имеет полный доступ ко всем организациям.
- Остальные пользователи видят только организации, членами которых являются, и работают по tenant-ролям.
- Регистрации нет; учётные записи создаются администратором.
- Доступ к любой КП/ПКП, файлу и документу требует авторизации.
- Видимость пространств, вкладок и колонок канбана настраивается ролями.

## Каталог

- Уникальность товара определяется группой, названием и маркировкой/размером. Поставщик и единица измерения в уникальность не входят.
- Если при вводе нового товара выбрана существующая группа текущего раздела, она сохраняется. Несуществующая или пустая группа не создаётся автоматически.
- Для нового товара без поставщика используется значение «не указан».
- Новый товар нельзя создать с нулевой ценой. При миграции явная нулевая цена заменяется на 1.
- Примечание необязательно и не участвует в уникальности.
- Группы доступны для всех категорий; для оборудования и материалов они организованы по категориям и разделам.
- Поставщики могут быть ограничены разделами.
- Несогласованный новый товар выделяется как новый; изменение существующего товара другим пользователем отражается отдельно от статуса согласования.
- Работы не привязаны к категории оборудования или материалов.
- Один товар может быть связан с нулём, одной или несколькими работами.
- Авторабота добавляет количество к уже существующей одинаковой работе и не сбрасывает вручную изменённые цену, скидку, наценку и количество.
- Если работа имеет одну маркировку, она выбирается автоматически; при нескольких маркировках пользователь выбирает сам.
- Монтажные работы отображаются перед демонтажными.

## Категории

- `equipment`: оборудование.
- `materials`: материалы.
- `work`: монтажные и демонтажные работы.
- `construction_works`: отдельная категория строительных работ.
- `incidental_expenses`: сопутствующие расходы; цена бывает фиксированной или процентом от суммы варианта.
- `maintenance`: обслуживание.
- `kits`: комплекты; доступны для добавления только в ПКП, группа «комплекты» назначается автоматически и не показывается пользователю.
- `consumables`: расходный материал; доступен для выбора только в комплектации, но управляется через общий каталог.

Фактическую доступность категорий в каждом builder необходимо оформить конфигурацией организации, сохранив перечисленные ограничения по умолчанию.

## КП и ПКП

- Предложение содержит один или несколько типов, каждый тип — один или несколько вариантов.
- Режим выбора задаёт либо один вариант, либо целый тип со всеми вариантами.
- Сводка варианта считается отдельно; сводка типа выводится после его вариантов.
- Заказчик и исполнитель обязательны для сохранения.
- Исполнитель по умолчанию — компания организации, отмеченная основной.
- Менеджер фиксируется при создании и не меняется при последующих сохранениях. Изменить менеджера и РОП может администратор с соответствующим разрешением.
- Статус, выбранный вариант/тип и даты изменений хранятся явно.
- Новые и изменённые пользователем строки не должны терять ручные значения при добавлении/удалении других строк или авторабот.
- Наценка может быть отрицательной и тогда уменьшает цену.
- Цена редактируется свободно; после выхода из поля значение ниже закупочной приравнивается к закупочной.
- Количество редактируется свободно; после выхода значение не больше нуля заменяется на 1.
- Скидка/наценка применяется к отмеченным строкам, а при отсутствии выбора — ко всем строкам раздела. Пустое поле применить нельзя, после применения поле очищается.
- Печать по шаблону должна структурно соответствовать документу, корректно переносить таблицы и не обрезать строки.

## Комплектация

- При переносе из КП адрес объекта получает название КП.
- Переносятся группы товаров и остальные пользовательские значения разрешённых позиций.
- Повторный переход статуса вернувшейся в КП карточки не создаёт новую комплектацию.
- В одной категории можно создавать несколько разных разделов, но нельзя создавать дубликат одного раздела.
- PDF-счетов может быть несколько; каждый можно открыть и удалить по правам.
- Черновик сохраняется локально при каждом изменении. При уходе с несохранёнными изменениями пользователь выбирает, оставить черновик или сбросить его.
- Автосохранение в базу по таймеру не используется.

## Документы

- Пользователь создаёт и версионирует шаблоны КП/ПКП.
- PDF формируется backend-сервисом и должен быть детерминированным.
- Табличные строки нельзя обрезать между страницами.
- Подпись располагается внизу страницы и учитывается при разбиении таблицы.
- Блоки компании и клиента выбирают конкретную запись либо используют источник КП.
- QR формируется из реквизитов выбранной компании.
- Для сложных документов предпочтителен поток секций и контейнеров, а не абсолютная координата каждой строки.

## Аудит и удаление

- Важные сущности удаляются мягко: `deleted_at`, `deleted_by`, `delete_reason`.
- Фоновая задача может переносить старые удалённые записи в архивную схему или базу.
- Аудитируются входы, выходы, создание, изменение, удаление, смена статуса, печать, экспорт и загрузка файлов.
- Для изменения цены товара, раздела товара и статусов КП/ПКП/комплектации хранится diff до/после.
