# Итерация 1. Аудит и проектирование

Дата аудита: 20 августа 2026 года.

## Результат

Зафиксированы устройство текущего приложения, данные полного дампа, обязательные бизнес-правила и целевая multi-tenant архитектура. Сформирован перечень записей и расхождений, которые нельзя исправлять или удалять без подтверждения владельца системы.

Исходными материалами были:

- действующий PHP-проект в `E:\Program Files\XAMPP\htdocs`;
- `schema.sql` из проекта;
- полный дамп `vebersg4_komp.sql.zip` от 20 августа 2026 года;
- существующие E2E-тесты;
- согласованные в задаче требования к новой системе.

## Зафиксированные решения

- Backend: ASP.NET Core REST API.
- Клиент: Flutter для Windows, macOS, Web, Android и iOS из одной кодовой базы с платформенными адаптерами.
- Данные: PostgreSQL, Redis, MinIO в разработке и S3-совместимое хранилище в production.
- Изоляция организаций: отдельная PostgreSQL-схема на организацию без `organization_id` в tenant-таблицах.
- Авторизация: JWT, refresh-токены, TOTP 2FA, управление сессиями устройств.
- Развёртывание: Docker Compose для разработки; production-конфигурация проектируется с внешними PostgreSQL, Redis и S3.
- Регистрация отсутствует. Учётные записи создаёт администратор; директор при первом входе создаёт и настраивает организацию.
- Публичных ссылок без авторизации в новой системе нет.
- Все важные действия и изменения критичных полей аудируются.
- Удаление мягкое; последующая архивация выполняется фоновой задачей.
- PDF формируется backend-сервисом.
- Черновики сохраняются локально как защита от потери данных, сервер остаётся источником истины.

## Границы итерации

На этой итерации не создавались ASP.NET/Flutter-проекты, контейнеры и новая схема PostgreSQL. Не выполнялись запросы к рабочей базе, не изменялись старые файлы и не удалялись данные. Следующая итерация начинается с каркаса решения и инфраструктуры.
