# Итерация 4. Каталог

## Цель

Итерация создаёт рабочий multi-tenant каталог поверх структуры, которую директор
организации настроил во время onboarding. Категории, разделы, группы, поля и
справочники не копируются: каталог читает материализованную конфигурацию tenant-а.

## Выполнено

- добавлена таблица `catalog_items` с мягким удалением и аудитом;
- уникальность обеспечивается по группе, нормализованному наименованию и
  маркировке; поставщик и единица измерения в индекс не входят;
- системные значения карточки хранятся отдельными колонками, настраиваемые поля —
  объектом `jsonb` с серверной проверкой реестра и типа;
- цена `base_price`, если передана, обязана быть больше нуля;
- добавлены REST endpoint-ы конфигурации, списка, одной карточки, создания,
  изменения и удаления;
- чтение защищено `catalog.view`, изменение — `catalog.manage`;
- создание, изменение и удаление записываются в `audit_log` с before/after diff;
- список имеет серверную пагинацию, поиск, фильтры категории, раздела и статуса.
- утверждён карточный вариант 2 и добавлен адаптивный Flutter-экран;
- рабочая оболочка сохраняет каталог, активные устройства и выход из системы;
- клиент разделён на модели, REST adapter, controller и UI;
- карточка строится по полям выбранной категории, включая обязательность,
  числовые типы, справочники, статус, раздел и группу;
- поиск использует debounce, фильтрация и пагинация выполняются на сервере;
- создание, редактирование и мягкое удаление работают через защищённый API;
- access token обновляется общим auth-механизмом без отдельной сессии каталога;
- на узком экране редактор открывается полноэкранно, на широком закреплён справа.
- рабочее пространство «Компания» редактирует всю конфигурацию организации через
  общий девятишаговый редактор без дублирования onboarding-логики;
- поля типа `dictionary` получили явный выбор справочника организации;
- выпадающие поля каталога и onboarding переведены на единый адаптивный компонент.
- редактор карточки разделён на вкладки «Основное», «Цены», «Остатки» и
  «Изображения»; все вкладки видны одновременно на узкой и широкой панели;
- «Остатки» пока являются явной заглушкой и не создают преждевременную модель
  складского учёта;
- изображения JPEG, PNG и WebP загружаются напрямую в закрытое S3/MinIO по
  pre-signed URL, а tenant-база хранит только проверенные метаданные;
- перед подтверждением backend сверяет MIME и размер объекта, ограничивает файл
  10 МБ и количество изображений одной карточки восемью;
- просмотр также использует короткоживущие ссылки, добавление и удаление
  защищены `catalog.manage` и записываются в аудит.
- настроенные зависимости категорий доступны каталогу без дублирования
  onboarding-конфигурации;
- одна карточка может содержать любое количество разных связанных карточек по
  UUID, а одна исходная карточка может использоваться в любом количестве
  целевых карточек;
- связи хранятся нормализованно, не содержат количества и не записываются в
  пользовательский JSON карточки;
- редактор получил вкладку «Связи» с серверным поиском, добавлением и удалением
  без перезагрузки страницы каталога.
- добавлены новые XLSX-шаблоны: отдельный лист на категорию, русские заголовки,
  скрытые стабильные коды и списки допустимых значений;
- экспорт выгружает весь выбранный раздел или весь каталог, независимо от
  текущей страницы Flutter-интерфейса;
- импорт выполняется одной транзакцией, использует общую серверную валидацию и
  создаёт либо обновляет карточку по её настроенной идентичности;
- массовое согласование, снятие согласования и мягкое удаление работают
  атомарно для выбранных карточек и записываются в аудит;
- Flutter-интерфейс получил выбор карточек, выбор текущей страницы и отдельные
  состояния загрузки, успеха и ошибки для файловых и массовых операций.
- XLSX версии 2 использует ID карточки как единственный признак обновления:
  заполненный ID обновляет указанную запись, пустой создаёт новую;
- поля связей экспортируют и импортируют UUID связанных карточек через `;`, а
  замена карточки и её связей выполняется одной транзакцией;
- списки Excel вынесены на скрытый служебный лист и подключены именованными
  диапазонами, чтобы Excel не восстанавливал содержимое книги при открытии.
