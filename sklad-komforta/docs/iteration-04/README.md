# Итерация 4. Каталог

## Цель

Итерация создаёт рабочий multi-tenant каталог поверх структуры, которую директор
организации настроил во время onboarding. Категории, разделы, группы, поля и
справочники не копируются: каталог читает материализованную конфигурацию tenant-а.

## Выполнено

- добавлена таблица `catalog_items` с мягким удалением и аудитом;
- уникальность обеспечивается по группе, нормализованному наименованию и
  маркировке; поставщик и единица измерения в индекс не входят;
- системные значения карточки хранятся отдельными колонками, настраиваемые поля —
  объектом `jsonb` с серверной проверкой реестра и типа;
- цена `base_price`, если передана, обязана быть больше нуля;
- добавлены REST endpoint-ы конфигурации, списка, одной карточки, создания,
  изменения и удаления;
- чтение защищено `catalog.view`, изменение — `catalog.manage`;
- создание, изменение и удаление записываются в `audit_log` с before/after diff;
- список имеет серверную пагинацию, поиск, фильтры категории, раздела и статуса.
- утверждён карточный вариант 2 и добавлен адаптивный Flutter-экран;
- рабочая оболочка сохраняет каталог, активные устройства и выход из системы;
- клиент разделён на модели, REST adapter, controller и UI;
- карточка строится по полям выбранной категории, включая обязательность,
  числовые типы, справочники, статус, раздел и группу;
- поиск использует debounce, фильтрация и пагинация выполняются на сервере;
- создание, редактирование и мягкое удаление работают через защищённый API;
- access token обновляется общим auth-механизмом без отдельной сессии каталога;
- на узком экране редактор открывается полноэкранно, на широком закреплён справа.
- рабочее пространство «Компания» редактирует всю конфигурацию организации через
  общий восьмишаговый редактор без дублирования onboarding-логики;
- поля типа `dictionary` получили явный выбор справочника организации;
- выпадающие поля каталога и onboarding переведены на единый адаптивный компонент.
