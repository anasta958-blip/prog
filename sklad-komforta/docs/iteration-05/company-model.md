# Модель пространства «Компания»

## Public-схема

### `public.organizations.active_until`

Единственный источник срока действия организации. Поле обязательно и индексировано
для активных организаций. Отдельная дата сотрудника намеренно не хранится: API
возвращает общий срок в каждой модели сотрудника, поэтому даты не расходятся.

### `public.organization_members.created_by`

Ссылка на пользователя, создавшего членство. У первого директора значение может
быть `NULL`, у сотрудников оно заполняется текущим пользователем.

## Tenant-схема

### `companies`

Хранит юридические лица. Общие реквизиты находятся в колонках, а сайт, директор,
подписант и банковские реквизиты — в существующем `details jsonb`. Форма
показывает разные реквизиты для ИП и организаций. Частичный уникальный индекс
сохраняет только одно активное юридическое лицо с `is_default = true`.

### `clients`

Справочник клиентов. Основные поля вынесены в колонки. В `details` хранятся тип
клиента, ИНН/КПП/ОГРН, данные объекта и получателя, банковские реквизиты,
паспортные данные и примечание. Это позволяет иметь отдельные формы физлица,
ИП и организации без создания параллельных таблиц.

### `employee_profiles`

Контактные данные сотрудника по `membership_id`. Учётные данные и активность
остаются в `public.users` и `public.organization_members`.

### `role_subordination`

Разрешённые пары `supervisor_role_id -> subordinate_role_id`. Самоссылка запрещена
CHECK-ограничением, транзитивные циклы проверяются до сохранения.

### `member_reporting`

Фактическая связь сотрудника с единственным непосредственным руководителем.
Первичный ключ по `membership_id` запрещает нескольких руководителей.

### `member_roles`

Миграция оставляет одну роль на членство и добавляет уникальный индекс. Для
директора при очистке старых множественных назначений приоритет имеет системная
роль «Директор».

## Миграции

- `migrations/public/0004_organization_lifecycle.sql`;
- `migrations/tenant/0014_company_workspace.sql`.

Новые tenant-ы получают обе модели автоматически. Для существующего volume
public-миграция и tenant-миграция применяются отдельно во время развёртывания.
