# Рабочее пространство канбанов

## Граница этапа

На этом этапе реализованы оболочка рабочего канбана, универсальные карточки и
управляемое перемещение карточек.
Экран отображает материализованные настройки организации: список канбанов,
столбцы, цвета, разрешённые переходы, категории и поля карточек.

Содержимое КП, ПКП и комплектаций, ссылки и варианты намеренно не входят в
универсальный модуль. Они будут
подключены отдельными сущностями, не изменяя базовый CRUD канбана.

## Backend

- `IKanbanService` предоставляет список канбанов, конфигурацию, страницы
  карточек и CRUD одной карточки.
- `PostgresKanbanService` читает `workflows`, `workflow_columns`,
  `workflow_transitions`, `workflow_categories` и
  `workflow_category_fields` из текущей tenant-схемы.
- `GET /api/v1/kanbans/` возвращает список канбанов.
- `GET /api/v1/kanbans/{id}` возвращает выбранный канбан.
- `GET /api/v1/kanbans/{id}/cards` возвращает страницу одного столбца.
- `POST`, `PUT` и `DELETE` на `/api/v1/kanbans/{id}/cards` создают,
  редактируют и мягко удаляют карточки.
- `POST /api/v1/kanbans/{id}/cards/{cardId}/move` атомарно меняет столбец и
  позицию карточки. Переход между столбцами разрешается только записью из
  `workflow_transitions`; порядок внутри текущего столбца можно менять всегда.
- Переносы одного канбана сериализуются транзакционной advisory-блокировкой,
  поэтому параллельные действия не создают одинаковый `sort_order`.
- Чтение защищено разрешением `kanban.view`. Создание, редактирование,
  удаление и перемещение независимо защищены правами `kanban.cards.create`,
  `kanban.cards.edit`, `kanban.cards.delete` и `kanban.cards.move`.
- Миграция `tenant/0022_kanban_cards.sql` добавляет `kanban_cards`, проверяет
  принадлежность столбца и категории канбану и создаёт индексы пагинации.
- Миграция `tenant/0023_kanban_sections_and_card_permissions.sql` переносит
  действия с карточками в права ролей, удаляет устаревшую настройку действий
  из категории и добавляет карточке проверяемую ссылку на раздел каталога.
- Миграция `tenant/0024_kanban_card_visibility.sql` хранит режим видимости
  карточек роли и нормализованный список сотрудников для точечного режима.
  Backend одинаково ограничивает список, прямое открытие, редактирование,
  перенос и удаление, поэтому скрытую карточку нельзя получить по её UUID.
- Режим `subordinates` рекурсивно включает всю нижестоящую ветку дерева
  сотрудников. Режим `specific` включает собственные карточки пользователя и
  карточки явно выбранных активных сотрудников. Системный полный доступ
  директора не ограничивается.
- Ограничения действий проверяются middleware API, поэтому их нельзя обойти
  прямым запросом. Роли со старым общим правом управления автоматически
  получают четыре новых права.
- Создание, изменение, перенос и удаление записываются в `audit_log` с состояниями
  до и после изменения.
- При сохранении конфигурации существующие связи канбана с категориями обновляются
  на месте. Используемые карточками категории не удаляются и не создаются повторно.

## Flutter

- `KanbanApi` отвечает только за REST-транспорт.
- `KanbanController` хранит отдельную страницу и индикатор загрузки для
  каждого столбца. CRUD перечитывает только изменённый столбец.
- `KanbanPage` реализует выбранный вариант 1: горизонтальные столбцы,
  компактные операционные карточки, desktop-панель и сворачиваемую
  mobile-панель.
- `KanbanCardEditor` строит форму из полей выбранной категории и её разделов.
  Единственный раздел выбирается автоматически, из нескольких пользователь
  выбирает один. Поддержаны текст, числа, деньги, проценты, флажки и справочники.
- В первичной и последующей настройке организации для каждой категории канбана
  задаётся только порядок выводимых полей. Действия с карточками настраиваются
  в правах ролей, а не дублируются в структуре полей.
- Порядок полей категории и полей карточки канбана меняется перетаскиванием за
  отдельную ручку. Элементы ввода, флажки и удаление не запускают перенос.
- В редакторе роли настройка «Видимость карточек» позволяет выбрать собственные,
  все, собственные с подчинёнными либо собственные с конкретными сотрудниками.
- В каждом столбце используется независимая серверная пагинация.
- На Desktop и Web горизонтальный холст перемещается зажатой левой кнопкой
  мыши; полоса прокрутки и обычная прокрутка также остаются доступными.
- Карточка переносится за любую точку её поверхности. Между карточками появляется
  точный маркер вставки, а у боковых краёв во время переноса работает горизонтальная
  автопрокрутка. После операции перечитываются только два затронутых столбца.
- Переключатель канбана использует единый `AppSelectField`: список открывается
  под полем, а при нехватке места снизу переносится над ним.
- При переключении канбана список не загружается повторно.
