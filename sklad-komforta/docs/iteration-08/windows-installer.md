# Установщик Windows для пользователя

Полный маршрут от сервера до клиента: [единый гайд](../virtualbox-server-from-zero.md).

## Назначение

Клиент для Windows 10 / Windows 11 x64 подключается к уже запущенному
серверу. База данных и Docker на компьютерах сотрудников не нужны.
Сервер, схема БД, UI и сгенерированные Flutter-файлы не изменяются.

`deploy/windows/installer.nsi` — русский мастер NSIS. Установка в
`%LOCALAPPDATA%\Programs\SkladKomforta` по умолчанию, без UAC (`RequestExecutionLevel user`).
Текущий сценарий также содержит страницу выбора папки; при обновлении проверьте,
что выбран прежний каталог. Особенности запоминания пути описаны в едином гайде.
Ярлык в меню «Пуск» создаётся для текущего пользователя; рабочий стол — по выбору.
Автозапуск, службы, правила firewall и системные библиотеки не устанавливаются.
Постоянный путь и ключ HKCU позволяют обновлять клиент следующим установщиком;
понижение версии блокируется. Перед установкой или удалением закрыть клиент.
Удаляются только файлы из списка сборки, не всё содержимое папки рекурсивно.
Удаление через настройки Windows удаляет установленные файлы, но не серверные
данные и не сохранённые учётные данные secure storage. На общем компьютере
перед удалением следует выйти из аккаунта; при утрате устройства отозвать сессию.

## Сборка

Требуются Windows x64, Python 3.11+, Flutter, Visual Studio с Desktop C++,
Windows SDK и NSIS 3 (makensis.exe). Условия лицензий инструментов,
включая redistributable Visual C++,
проверяет владелец выпуска. Скрипт не устанавливает инструменты автоматически.

Из корня `sklad-komforta`:

```powershell
python scripts/build_windows_installer.py --app-url https://app.skladkomforta.dpdns.org
```

Параметры: `--flutter` — путь flutter.bat, `--makensis` — путь makensis.exe,
`--crt-dir` — каталог redistributable x64 Microsoft.VC*.CRT из Visual Studio.
`--prepare-only` собирает и проверяет bundle без установщика. NSIS можно
распаковать из официального ZIP в `build/tools/nsis-3.12`: установки в систему
не требуется, этот путь определяется автоматически. Inno Setup не используется.
NSIS допускает коммерческое использование; выбран встроенный компрессор zlib.

Скрипт всегда выполняет Flutter release x64 с `APP_ENVIRONMENT=production`,
`API_BASE_URL=<app-url>/api/v1`, `PUBLIC_APP_BASE_URL=<app-url>`.
Принимается только HTTPS-домен без пути, порта, учётных данных и параметров.
Версия читается из pubspec.yaml: major.minor.patch+build, числа до 65535.
Каждый выпуск получает отдельный каталог `build/windows-installer/` без
перезаписи предыдущих. Существующую Flutter release-сборку обновляет Flutter.
Нельзя одновременно запускать две сборки в одном рабочем дереве.

В bundle копируются только release-файлы Flutter и redistributable x64 CRT;
`.env`, закрытые ключи и серверные каталоги не читаются. Проверяются обязательные
DLL, assets, app.so и отсутствие файлов секретов. Ненулевой код инструментов
останавливает сборку. Установщик включает весь bundle, а не только EXE.
Локальный CRT нужен для работы без прав администратора; его обновления следует
распространять новыми выпусками клиента, Windows Update его не обслуживает.

Результаты: `SkladKomforta-<версия>-windows-x64-setup.exe`, SHA-256 рядом,
`release.json` (домен, версия, commit, dirty, время, CRT и хеш установщика).
Артефакты в build не коммитятся. Перед публичным выпуском нужен зафиксированный
код; dirty-сборка предназначена для проверки. Скрипт не коммитит и не публикует.
Пароли, токены Cloudflare и ключ TOTP внутрь клиента не включаются.

## Проверки и ограничения

```powershell
python -m unittest discover -s tests/windows-installer -v
cd src/flutter
flutter analyze
flutter test
```

Unit-тесты проверяют URL, версии, release-параметры, комплектность и отсутствие
секретов в bundle, пользовательский режим установки. Они не заменяют проверку
самого установщика. Перед раздачей проверить установку под обычным пользователем
без UAC, запуск, вход/TOTP, файл/PDF, ссылку КП, обновление поверх предыдущей
версии и удаление. Нужна отдельная проверка на чистой Windows без Visual Studio.

По умолчанию установщик НЕ подписан сертификатом издателя: возможны предупреждения
SmartScreen/антивируса и запрет запуска политиками организации. Подпись и автоматическое
обновление пока не настроены. Не отключать защиту Windows ради установки.
Для распространения нужен доверенный канал и контроль SHA-256; файл пока не
размещается автоматически на сервере. Использование приложения требует интернета.

Источники: [NSIS, пользовательская установка](https://nsis.sourceforge.io/Reference/RequestExecutionLevel),
[лицензия NSIS](https://nsis.sourceforge.io/Docs/AppendixI.html),
[Flutter Windows](https://docs.flutter.dev/deployment/windows),
[локальное размещение CRT](https://learn.microsoft.com/en-us/cpp/windows/deployment-in-visual-cpp).

## Проверено 11.10.2026

- Flutter 3.38.9, Visual Studio 2022, NSIS 3.12 portable с официального SourceForge.
- `flutter analyze`: замечаний нет; все 194 Flutter-теста пройдены.
- 9 unit-тестов упаковки пройдены, включая точный список удаления и экранирование NSIS.
- Release 1.0.0+1 собран для `https://app.skladkomforta.dpdns.org`.
- NSIS-установка и повторная установка в профиль пользователя завершились с кодом 0.
  Все 30 файлов установленного bundle совпали с оригиналом по SHA-256.
- Штатное удаление завершилось с кодом 0: папка приложения, ярлык и HKCU-запись удалены.
  До проверки подтверждено отсутствие прежней установки; чужая установка не затрагивалась.
- На момент автоматической проверки чистая Windows без инструментов разработки,
  визуальный мастер, вход, PDF и файлы не проверялись. Позднее владелец сообщил,
  что клиент работает; это не подтверждает каждый пункт матрицы приёмки отдельно.
  Подписи издателя нет.
- Установщик не опубликован в интернете; коммит и push не выполнялись.

Промежуточный пакет Inno Setup не предназначен для распространения: по решению
владельца проект переведён на NSIS. Сценарий Inno удалён, параллельной упаковки нет.
