# Android APK для прямой установки

## Назначение и конфигурация

`scripts/build_android_apk.py` собирает подписанный универсальный release APK
без Google Play и без изменения сервера. Windows, Python 3.11+, Flutter,
Android Studio/JDK и Android SDK должны быть установлены. Лицензии SDK принимает
владелец компьютера. CLI не принимает их автоматически.

Скрипт повторно использует проверки HTTPS-адреса и версии из
`build_windows_installer.py`; NSIS и Visual Studio для Android не нужны.
Команды `init-signing` и `build` отделены: обычная сборка никогда не создаёт
и не заменяет ключ. `--flutter`, `--java-home`, `--android-sdk` задают пути
инструментов; `--signing-dir` переопределяет каталог закрытого ключа.
Только `build` требует `--app-url` — HTTPS-домен без пути и параметров.

Параметры Flutter: `API_BASE_URL=<app-url>/api/v1`,
`PUBLIC_APP_BASE_URL=<app-url>`, `APP_ENVIRONMENT=production`.
Миграций, изменений API, расчётов и UI-контроллеров нет.

## Подпись и резервная копия

Один раз из корня проекта в PowerShell:

```powershell
python scripts/build_android_apk.py init-signing
```

По умолчанию ключ создаётся в `%USERPROFILE%\.sklad-komforta\android-signing`,
вне Git-репозитория, с закрытой ACL для текущей учётной записи Windows.
Системные привилегии SYSTEM/администраторов сохраняются; обычным другим
пользователям доступ не предоставляется.
Существующий каталог не перезаписывается. При ошибке создания не удалять папку
вслепую: сначала проверить, не создан ли уже ключ.

- `release.p12` — постоянный закрытый ключ RSA 3072, сертификат на 10000 дней.
- `password.txt` — случайный пароль PKCS12; alias ключа `skladkomforta`.

Нужно сохранить оба файла на защищённый внешний носитель. Не отправлять их
в чат, GitHub, вместе с APK или сотрудникам. Пароль передаётся keytool через
файл, не аргументом процесса; содержимое не печатается. Потеря ключа/пароля
лишит возможности обновлять уже установленное приложение той же подписью.
Это отдельный ключ, не ключ серверных резервных копий и не токен Cloudflare.

Gradle читает каталог из `SKLAD_ANDROID_SIGNING_DIR` (скрипт задаёт его только
для дочернего процесса). Release без каталога подписи завершается ошибкой;
fallback на debug key удалён. Обычная debug-разработка сохраняется.

## Сборка и результаты

```powershell
python scripts/build_android_apk.py build --app-url https://app.skladkomforta.dpdns.org --flutter "D:\develop\flutter\bin\flutter.bat" --android-sdk "E:\Android\Sdk"
```

Версия берётся из `src/flutter/pubspec.yaml`, например `1.0.0+1`.
Для обновлений увеличивать номер после `+`, не менять applicationId
`com.skladkomforta.sklad_komforta_app` и использовать тот же ключ.
Одновременно несколько сборок в одном рабочем дереве не запускать.
Сценарий release отключает инкрементальную Kotlin-компиляцию только через
окружение дочернего процесса: кэш Kotlin не поддерживает относительные пути,
когда Pub Cache и проект находятся на разных дисках Windows. Файлы глобальных
настроек и обычная debug-сборка не меняются.

После Flutter build запускается `apksigner verify --verbose --print-certs`.
SHA-256 сертификата сверяется с сертификатом из PKCS12. Через `aapt` проверяются
package ID, INTERNET и отсутствие debuggable. Только затем APK копируется в
новую папку `build/android-apk/<версия>-<суффикс>`.
В ней APK, `.apk.sha256`, `release.json` (версия, домен, commit, dirty, хеши)
и `apk-verification.txt` (публичный сертификат, SDK/ABI/разрешения).
Артефакты не коммитятся; ключ и пароль в них не копируются.

Android manifest содержит INTERNET и русское название «Склад Комфорта».
Резервное копирование приложения отключено согласно рекомендации secure storage,
чтобы не переносить зашифрованные токены без аппаратных ключей. Данные организации
хранятся на сервере. Разрешение HTTP остаётся только в debug-манифесте.

## Проверка и установка

```powershell
python -m unittest discover -s tests/android-apk -v
cd src/flutter
flutter analyze
flutter test
```

Тесты проверяют production URL, защиту каталога ключей от перезаписи,
разбор сертификата и SDK, INTERNET, backup и запрет debug-подписи release.
Они не заменяют запуск APK. Перед распространением проверить на телефоне:
установку, вход/TOTP, каталог, загрузку изображения, PDF, ссылки, повторный запуск
и обновление поверх существующей версии с сохранением доступа к аккаунту.

Передать на телефон только APK. Android может потребовать разрешить установку
из конкретного браузера/файлового менеджера; после установки разрешение можно
отозвать. Play Protect не отключать. Если ранее стояла debug-версия с тем же
applicationId, подписи отличаются: обновить её release APK нельзя. Не удалять
её без понимания, что локальное состояние будет потеряно; серверные данные остаются.
Автообновление, Google Play, подтверждение разработчика Android и публикация
ссылки скачивания этой задачей не настраиваются.

Источники: [Flutter Android release](https://docs.flutter.dev/deployment/android),
[подпись Android](https://developer.android.com/studio/publish/app-signing),
[flutter_secure_storage](https://pub.dev/packages/flutter_secure_storage).
