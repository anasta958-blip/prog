# Итерация 2. Технический каркас

## Результат

Создан отдельный компилируемый каркас новой системы:

- solution на .NET 10 с разделением `Api`, `Application`, `Domain`, `Infrastructure`, `Worker`;
- один Flutter-проект для Windows, macOS, Web, Android и iOS;
- PostgreSQL schema-per-tenant без `organization_id` в tenant-таблицах;
- Redis-адаптер кэша;
- S3-совместимый адаптер файлов с pre-signed URL для MinIO и облачного S3;
- Docker Compose для PostgreSQL, Redis, MinIO, Mailpit, API и Worker;
- JWT middleware и правила срока access/refresh токенов;
- unit, API integration и Flutter widget тесты.

Подробное назначение ручных файлов, классов и функций приведено в [составе компонентов](components.md). Правила обязательного документирования следующего кода находятся в [общем стандарте](../documentation-rules.md).

## Что намеренно не сделано

- Нет регистрации и onboarding: они относятся к первому модулю `Авторизация`.
- Нет бизнес-таблиц каталога, КП, комплектации и документов. Их схема добавляется вместе с модулями, чтобы не закрепить ошибочные связи до миграции данных.
- Нет бизнес-экранов Flutter. Сначала для каждого экрана готовятся три изображения и согласуется один вариант.
- Старый PHP-проект и MySQL-дамп не изменялись.

## Возможная следующая итерация

Модуль авторизации: одноразовое создание директора, первый вход, TOTP, JWT/refresh sessions, управление устройствами и создание организации с tenant-схемой. Эта итерация не начинается без отдельной команды пользователя.
