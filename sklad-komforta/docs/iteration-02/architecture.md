# Структура и границы

## Backend

- `SkladKomforta.Domain`: правила, не зависящие от транспорта и хранения. Сейчас здесь безопасное имя tenant-схемы и сроки токенов по типу устройства.
- `SkladKomforta.Application`: контракты use case-слоя и интерфейсы инфраструктуры.
- `SkladKomforta.Infrastructure`: PostgreSQL, Redis, S3, tenant-контекст и проверка зависимостей.
- `SkladKomforta.Api`: HTTP pipeline, JWT, tenant resolution, единый ответ и health endpoints.
- `SkladKomforta.Worker`: будущие фоновые задачи архивации, уведомлений и PDF.

Зависимости направлены внутрь: `Api/Worker -> Infrastructure -> Application -> Domain`. Domain не знает о PostgreSQL, Redis, HTTP или Flutter.

## Multi-tenant

`public` хранит глобальную идентификацию:

- пользователей и TOTP;
- организации и членство;
- refresh-сессии устройств;
- версии tenant-миграций;
- аудит безопасности.

Каждая организация получает схему `tenant_<uuid без дефисов>`. В ней находятся собственные роли, права и рабочие данные. `organization_id` в tenant-таблицах отсутствует. Имя схемы генерируется сервером и проверяется регулярным выражением; значение из HTTP не используется как SQL-идентификатор.

Администратор с полным доступом будет обрабатываться серверной политикой. Остальные роли и права принадлежат tenant-схеме и создаются директором организации.

## Файлы

`IObjectStorage` не зависит от MinIO. Для разработки рабочий `AmazonS3Client` указывает на внутренний адрес MinIO, а отдельный signer использует публичный адрес, доступный клиенту. Это важно: host входит в S3-подпись и не может быть заменён после её создания. В production меняются URL, регион и реквизиты доступа. Прямой анонимный доступ к bucket запрещён, клиент получает короткоживущие pre-signed URL после серверной проверки прав.

## Flutter

`src/flutter` является единым исходным проектом. Web, Windows, macOS, Android и iOS используют общие Domain/UI/use case слои, но сохраняют платформенные каталоги для подписи, разрешений и нативных адаптеров. API URL и среда задаются через `--dart-define`, поэтому код не привязан к локальному серверу.

Каталог `macos/` создан штатной командой Flutter и зарегистрирован в `.metadata`. Swift/Xcode-файлы являются генерируемой платформенной оболочкой: в них вносятся только действительно необходимые нативные настройки, чтобы обновление Flutter не уничтожало ручную бизнес-логику.
