# Миграции

- `public/` содержит общие таблицы авторизации, организаций, членства и сессий.
- `tenant/` содержит шаблоны для отдельной схемы каждой организации.
- `__TENANT_SCHEMA__` заменяется только серверным provisioner-ом на имя, созданное через `TenantSchemaName.Create`. Значение из HTTP-запроса в SQL не подставляется.
- Новые изменения добавляются отдельным последовательным файлом. Уже применённые миграции не редактируются.

`tenant/0003_organization_configuration.sql` создаёт только конфигурационный
каркас будущих модулей: профиль, структуру канбанов и каталога, определения
полей, роли и справочники. Таблицы самих товаров, КП, комплектаций и документов
будут добавляться вместе с соответствующими модулями после проверки миграции
старых данных.

`tenant/0004_catalog_category_fields.sql` добавляет упорядоченную связь категории
с полями системного реестра. В таблице хранятся только код, видимость,
обязательность и порядок; название, тип и расчётная семантика поля задаются
приложением и повторно проверяются backend-ом.

`tenant/0005_catalog_category_dependencies.sql` расширяет onboarding до восьми
шагов и хранит разрешённые связи между категориями. Каждая запись указывает,
позиции какой категории можно привязать к позиции другой категории и в какое
relation-поле целевой карточки записывается связь.

`tenant/0006_workflow_categories.sql` связывает каждый канбан с выбранными
категориями каталога и хранит отдельный упорядоченный набор полей карточки для
каждой пары. Поля выбираются только из фактической настройки категории;
результаты формул не создают отдельные поля карточки автоматически.

`tenant/0007_remove_retail_price_field.sql` удаляет устаревшее поле `retail_price`
из настроек категорий, канбанов и контекстов. Рабочие цены товаров миграция не
изменяет; актуальным полем настройки цены остаётся `base_price`.

`tenant/0008_normalize_default_price_fields.sql` однократно очищает старые
onboarding-черновики от ранее автоматически добавлявшихся розничной цены,
скидки и наценки. После миграции скидку и наценку можно добавить вручную.

`tenant/0009_remove_default_line_total.sql` однократно убирает расчётное поле
`line_total` из ранее созданных стандартных наборов. Результаты расчётов
настраиваются правилами и не добавляются как обычные поля рабочей карточки.

`tenant/0010_catalog_items.sql` создаёт рабочие карточки каталога, составные
ограничения принадлежности разделов и групп, индексы фильтрации и уникальность
по группе, наименованию и маркировке. Карточки удаляются мягко.

`tenant/0011_field_dictionary_bindings.sql` добавляет явную привязку справочника
к полю категории и к полю бизнес-контекста. Ссылка хранится по стабильному коду
справочника и очищается при удалении справочника, не удаляя само поле.

`tenant/0018_catalog_field_labels.sql` сохраняет настраиваемое отображаемое
название поля внутри категории, не меняя технический код системного поля.

`tenant/0019_custom_catalog_field_types.sql` добавляет хранимый тип поля.
Системные поля получают тип из реестра, а пользовательские поля создаются с
автоматическим техническим кодом, выбранным типом и собственным названием.

`tenant/0020_onboarding_rules_and_calculations.sql` разрешает девятый шаг
настройки организации «Правила и расчёты». Сами правила, формулы и сопоставления
денежного конвейера входят в JSONB-черновик настройки, поэтому отдельные таблицы
и перенос существующих данных не требуются.

`tenant/0023_kanban_sections_and_card_permissions.sql` заменяет общее право
управления канбаном четырьмя независимыми действиями роли и добавляет карточке
ссылку на раздел её категории. Единственный раздел может назначаться
автоматически, а выбор из нескольких проверяется backend-ом.

`tenant/0024_kanban_card_visibility.sql` добавляет роли серверное ограничение
видимости карточек канбана: свои, все, свои и нижестоящей ветки либо свои и
явно выбранных сотрудников. Существующие роли сохраняют прежний полный обзор,
а новые роли по умолчанию видят только собственные карточки.
